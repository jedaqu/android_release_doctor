# M0.8 Block 2 — CLI Output Contract

Date: 2026-10-01
Status: frozen implementation contract

## 1. Purpose

Define the stable command-line behavior that exposes the Report v1 contract without changing the audit engine.

## 2. Existing command

The CLI continues to accept one APK/AAB artifact plus the existing optional project and Play arguments:

`android-release-doctor [options] <release.apk|release.aab>`

Existing options:
- `--project <android-module>`
- `--play`
- `--play-platform <mobile|wear|automotive|tv|xr>`

## 3. New options

### `--format <text|json>`

Selects the report format.

Default:
`text`

`text`:
- preserves the existing human-readable report byte content;
- remains stdout by default.

`json`:
- emits the frozen Report v1 object;
- uses the existing `ReportV1Context` to preserve Play context;
- uses compact JSON serialization;
- adds exactly one trailing newline at the CLI boundary.

No new schema is created by Block 2.

### `--output <path>`

Redirects the selected report to the specified file.

Behavior:
- report bytes go to the file;
- stdout remains empty;
- diagnostics remain stderr;
- existing files may be replaced;
- any write/create failure returns exit code 2.

### `--help`

Prints CLI usage and option descriptions to stdout and exits 0.

It is a standalone meta command. Combining it with report-execution arguments is a usage error.

### `--version`

Prints:

`android-release-doctor <engine-version>`

to stdout and exits 0.

It is a standalone meta command. Combining it with report-execution arguments is a usage error.

## 4. Stream contract

### stdout

Must contain only the selected report or standalone meta-command output.

For JSON execution, stdout must contain valid JSON only, with one trailing newline.

### stderr

Must contain only diagnostics:
- invalid arguments;
- invalid option values;
- input/audit failure;
- output-file failure;
- serialization/internal CLI failure.

The CLI must never write a human-readable prefix to JSON stdout.

## 5. Exit codes

`0`:
- audit completed;
- zero BLOCKER findings.

`1`:
- audit completed;
- one or more BLOCKER findings.

`2`:
- usage error;
- invalid/missing input;
- audit failure before a report can be emitted;
- report output-file failure;
- serialization/internal CLI failure.

MANUAL-REVIEW findings do not produce exit code 1.

## 6. Validation rules

The CLI rejects:
- unknown options;
- missing option values;
- duplicate options where a single value/occurrence is defined;
- invalid `--format` values;
- `--play-platform` without `--play`;
- missing artifact;
- more than one artifact;
- report-execution arguments combined with `--help` or `--version`.

Option ordering is unrestricted.

## 7. Compatibility rule

The default invocation remains:

`android-release-doctor <release.apk|release.aab>`

It keeps:
- text output;
- stdout report;
- blocker exit code 1;
- usage/audit error exit code 2.

Therefore existing terminal and CI callers do not need to change to obtain the previous behavior.

## 8. Relationship to Report v1

Block 2 is an output/control-plane contract.

The report body remains exactly the M0.8 Block 1 Report v1 contract:
- `schema_version = "1.0"`;
- same top-level fields;
- same evidence semantics;
- same null/empty/false/error rules.

CLI options do not alter the report schema.

## 9. Explicitly out of scope

- CLI framework migration;
- batch/multi-artifact input;
- SARIF/HTML;
- GitHub Action;
- release packaging;
- new audit rules;
- cryptographic changes;
- Report v1 schema changes;
- new exit codes beyond 0/1/2.
