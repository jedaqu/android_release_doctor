# M0.8 Block 3 — GitHub Action Contract

Date: 2026-10-01
Status: frozen implementation contract

## 1. Purpose

Expose Android Release Doctor as a reusable GitHub composite action while preserving the already-frozen CLI and Report v1 contracts.

The action is an orchestration layer only. It does not implement audit rules.

## 2. Location and invocation

Action metadata:

`.github/actions/android-release-doctor/action.yml`

External usage:

`jedaqu/android-release-doctor/.github/actions/android-release-doctor@<ref>`

For same-repository testing, the workflow may reference the local action path.

## 3. Inputs

### `artifact`

Required path to exactly one APK or AAB.

The path is interpreted from the workflow workspace, or may be absolute.

### `project`

Optional Android application-module path passed to the CLI as `--project`.

### `play`

Optional boolean-like input. Default: `false`.

When `true`, the action passes `--play`.

### `play-platform`

Optional platform. Default: `mobile`.

The value is passed unchanged to the CLI when `--play` is active.

The CLI remains authoritative for allowed values and dependency validation.

### `format`

Optional output format. Default: `text`.

Allowed values are the CLI contract values:
- `text`
- `json`

### `output`

Optional report destination.

When set, the action passes `--output <path>`.
When empty, the report remains on stdout as defined by the CLI.

## 4. Outputs

### `exit-code`

The exact numeric exit code returned by Android Release Doctor:
- `0`
- `1`
- `2`

### `report-path`

The supplied output path when `output` is set; otherwise an empty string.

The action does not invent a default report path.

## 5. Execution model

The action invokes:

`cargo run --quiet --manifest-path <action-repository-root>/Cargo.toml -p doctor-cli -- ...`

The action repository source is resolved through `GITHUB_ACTION_PATH`; because the action metadata lives under `.github/actions/android-release-doctor/`, the workspace manifest is addressed through `GITHUB_ACTION_PATH/../../../Cargo.toml`.

The action does not:
- invoke Gradle;
- invoke Android SDK tools;
- execute external packaging/signing commands;
- alter artifact contents;
- alter Report v1;
- modify audit semantics.

A runner with a usable Rust/Cargo toolchain is a Block 3 prerequisite. Provisioning a prebuilt binary/toolchain image is reserved for future distribution work.

## 6. Exit semantics

The action preserves the CLI exit status.

- `0`: action succeeds;
- `1`: action fails because the audit found one or more blockers;
- `2`: action fails because of usage, input, audit, output, serialization, or internal error.

The action must still publish `exit-code` and `report-path` before returning the non-zero status.

## 7. Report semantics

No report schema exists at the action layer.

The action simply selects:
- CLI text output; or
- CLI JSON output, which remains Report v1 schema `1.0`.

When `output` is set, report bytes are written by the CLI exactly as specified by the Block 2 contract.

## 8. Security and scope constraints

Inputs are passed to the CLI as shell arguments without interpolation into executable code.

The action must not:
- download arbitrary scripts;
- evaluate user-supplied shell code;
- add telemetry;
- upload artifacts automatically;
- publish secrets;
- create releases.

## 9. Focused validation

The Block 3 self-test workflow must verify:
- successful audit;
- JSON output and Report v1 marker;
- requested output-file creation;
- blocker exit code `1`;
- blocker report preservation.

CLI-specific edge cases remain covered by Block 2 integration tests.
