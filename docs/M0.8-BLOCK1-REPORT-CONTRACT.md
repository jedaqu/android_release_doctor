# M0.8 Block 1 — Report Contract v1

Date: 2026-10-01
Contract status: definition candidate
Schema version: `1.0`

## 1. Purpose

This contract defines the stable machine-readable representation of evidence already produced by Android Release Doctor.

It is a public output contract, not a serialization of internal Rust structs.

## 2. Top-level object

Required:

- `schema_version`: string, exactly `"1.0"`
- `engine_version`: string
- `artifact`: object
- `application`: object or null
- `manifest_error`: string or null
- `inventory`: object
- `project`: object or null
- `project_error`: string or null
- `play`: object or null
- `findings`: array
- `summary`: object

### Determinism rule

No generated timestamp is part of v1.

No host environment object is part of v1.

No invented artifact hash is part of v1.

## 3. Artifact

```json
{
  "kind": "APK | AAB",
  "path": "string",
  "size_bytes": 0
}
```

The path is the path supplied to the engine. Consumers must not infer a host-specific path format.

## 4. Application

When a manifest is successfully parsed:

```json
{
  "package_name": "string | null",
  "version_code": 0,
  "version_name": "string | null",
  "min_sdk": 0,
  "target_sdk": 0,
  "debuggable": true,
  "permissions": [],
  "components": [
    {
      "kind": "string",
      "name": "string",
      "exported": true,
      "has_intent_filters": true
    }
  ]
}
```

When no parsed manifest is available, `application` is `null`. The dedicated top-level `manifest_error` records a parsing error when one exists.

## 5. Inventory

```json
{
  "entries": [],
  "manifest_path": "string | null",
  "dex_files": [],
  "native_abis": [],
  "native_libraries": [],
  "native_zip_entries": [],
  "signature_files": [],
  "apk_signing": null,
  "apk_signing_error": "string | null",
  "apk_signature_verification": null,
  "apk_signature_verification_error": "string | null"
}
```

### Native library

```json
{
  "path": "string",
  "abi": "string",
  "load_segment_alignments": [],
  "error": "string | null"
}
```

### Native ZIP entry

```json
{
  "path": "string",
  "abi": "string",
  "compression": "stored | compressed",
  "data_offset": 0,
  "alignment_16kb": true,
  "error": "string | null"
}
```

### APK signing structure

```json
{
  "v2": true,
  "v3": true,
  "v31": false,
  "v32": false,
  "block_size": 0
}
```

Boolean presence fields are evidence-backed observations. They are not verification states.

## 6. Cryptographic verification

`apk_signature_verification` is either an object or `null`.

```json
{
  "v2": null,
  "v3": null,
  "v31": null,
  "v31_present": false,
  "v32_present": false
}
```

A scheme object:

```json
{
  "state": "verified | invalid | unsupported",
  "signer_count": 0,
  "algorithms": [],
  "certificate_sha256": [],
  "sdk_ranges": [
    [28, 36]
  ],
  "rotation_min_sdk": null,
  "rotation_targets_dev_release": false,
  "proof_of_rotation": [],
  "detail": "string"
}
```

### Proof-of-rotation

```json
{
  "state": "verified | invalid | unsupported",
  "level_count": 0,
  "lineage_certificate_sha256": [],
  "capabilities": [],
  "detail": "string"
}
```

### Capability evidence

```json
{
  "flags": 0,
  "known_flags": 0,
  "unknown_flags": 0,
  "installed_data": false,
  "shared_user_id": false,
  "permission": false,
  "rollback": false,
  "auth": false
}
```

The report must preserve `unknown_flags` instead of silently discarding unknown/reserved capability bits.

## 7. Project evidence

`project` is null when project evidence was not produced successfully.

When available:

```json
{
  "build_file": "string",
  "syntax": "Groovy | Kotlin DSL",
  "module_name": "string",
  "namespace": "string | null",
  "application_id": "string | null",
  "compile_sdk": 0,
  "min_sdk": 0,
  "target_sdk": 0,
  "version_code": 0,
  "version_name": "string | null",
  "release_debuggable": true
}
```

`project_error` is null when no project error occurred. A non-null `project_error` means project analysis was requested but failed; it is not equivalent to a valid project object.

## 8. Play context

`play` is null unless Play evaluation was requested.

When present:

```json
{
  "platform": "mobile | wear | automotive | tv | xr",
  "policy_version": "string"
}
```

This context identifies which profile produced Play findings. It does not itself assert Play Console completion.

## 9. Findings

Each finding is:

```json
{
  "rule_id": "string",
  "severity": "PASS | WARNING | BLOCKER | MANUAL-REVIEW",
  "title": "string",
  "summary": "string",
  "remediation": "string"
}
```

The rule ID is the stable automation key.

Human-readable text is not a stable automation key and must not be used as the consumer's primary selector.

## 10. Summary

```json
{
  "passed": 0,
  "warnings": 0,
  "blockers": 0,
  "manual_review": 0
}
```

The counts must equal the findings collection exactly.

Manual-review findings are not blockers and are not passes.

Exit codes are deliberately outside this contract.

## 11. Null vs empty rules

- `null` = optional evidence object/value was not produced.
- `[]` = the engine produced and inspected the collection, and it contains zero entries.
- `false` = an explicit negative observation.
- an error string = inspection/parsing failed for that evidence family.

Consumers must not reinterpret one state as another.

## 12. Compatibility

Consumers select behavior by `schema_version`.

Allowed future changes:

- patch: wording/metadata only;
- minor: additive optional fields;
- major: incompatible structural or semantic changes.

The engine version may change without changing report semantics.

## 13. Implementation constraint

Production code must introduce explicit v1 DTOs rather than deriving serialization directly from domain structs.

Recommended implementation boundary:

```text
AuditReport
    |
    v1 report mapper + execution context
    v
ReportV1 DTO
    |
    v
JSON serializer
```

The mapper receives Play context separately because the current `AuditReport` does not retain that invocation context.

The existing text renderer remains independent.

## 14. Completion boundary

This document freezes the semantics for M0.8 Block 1.

It does not implement serialization, CLI flags, GitHub Action behavior, or release packaging.
